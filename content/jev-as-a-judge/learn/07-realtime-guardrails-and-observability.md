# Real-Time Guardrails & LLM Observability

Deploying Large Language Models in customer-facing production systems requires continuous monitoring to detect hallucinations, toxic content, and prompt injection attacks. Because traditional generative judges are too slow and expensive for high-volume traffic, **JEV decision-only cascades serve as the foundational engine for real-time AI guardrails and telemetry**.

---

## 1. Inline Guardrails vs. Asynchronous Shadow Telemetry

Production evaluation operates in two primary deployment topologies:

```text
1. INLINE SYNCHRONOUS GUARDRAILS (Blocks Malicious / Hallucinated Outputs)
[ Client ] <--- Blocks if JEV Fail --- [ JEV Guardrail (30ms) ] <--- [ Production LLM ]
* Protects user in real-time. Requires sub-50ms execution!

2. ASYNCHRONOUS SHADOW OBSERVABILITY (Continuous Production Auditing)
[ Client ] <-------------------- Stream Response -------------------- [ Production LLM ]
                                                                           |
                                  +----------------------------------------+
                                  | Asynchronous Event Log
                                  v
                        [ JEV Telemetry Pipeline ]
                                  |
              Log to Langfuse / LangSmith / Arize Phoenix
```

### Inline Synchronous Mode
The evaluator sits directly on the request-response path. If the model generates an ungrounded claim or violates safety guidelines, JEV intercepts the stream, aborts the response, and substitutes a safe fallback message.

### Asynchronous Shadow Mode
The user receives the model stream without delay. Concurrently, the user prompt, retrieved context, and generated response are enqueued to a message broker (e.g., Apache Kafka) for background JEV evaluation.

## 2. Real-Time Telemetry Metrics

Production observability dashboards track four critical signals generated by the JEV cascade:

```text
+---------------------------------------------------------------+
|                 JEV OBSERVABILITY DASHBOARD                   |
|                                                               |
|  1. Escalation Rate (alpha): 14.2%  [NORMAL]                  |
|  2. Average JEV Latency:    38ms    [HEALTHY]                 |
|  3. Faithfulness Score:     97.4%   [EXCELLENT]               |
|  4. Tier 2 Monthly Burn:    $840    [-84% vs Baseline]        |
+---------------------------------------------------------------+
```

### 1. Escalation Rate Spikes ($\alpha$ Trend)
Under normal operations, the escalation rate hovers between $12\%$ and $18\%$.
- **If $\alpha$ suddenly spikes to $45\%$:** Indicates **Data Drift** (new user query patterns the model hasn't encountered), a surge in complex edge cases, or coordinated adversarial prompt injection attacks!

### 2. Tail Latency Metrics (p95 / p99)
Ensures that Tier 1 JEV evaluations execute within the strict $50\text{ms}$ budget, avoiding thread starvation in upstream gateway proxies.

### 3. Cumulative Cost Savings Rate
Calculates real-time financial savings compared to running frontier reasoning models across $100\%$ of transactions:

$$\text{Savings} = 1.0 - \frac{\text{Actual Cost}_{\text{Cascade}}}{\text{Theoretical Cost}_{\text{All-Frontier}}}$$

## 3. Integrating with Modern Observability Stacks

JEV pipelines integrate natively into observability frameworks (such as **Langfuse**, **LangSmith**, and **OpenTelemetry**):

```python
# OpenTelemetry instrumentation for JEV evaluation
from opentelemetry import trace

tracer = trace.get_tracer("ai.guardrail")

def evaluate_and_record(prompt: str, response: str, context: str):
    with tracer.start_as_current_span("jev_evaluation") as span:
        result = cascade.evaluate(prompt, response, context)
        
        # Attach structured telemetry attributes
        span.set_attribute("eval.verdict", result.verdict)
        span.set_attribute("eval.confidence", result.confidence)
        span.set_attribute("eval.tier", result.tier)
        span.set_attribute("eval.latency_ms", result.latency_ms)
        span.set_attribute("eval.cost_usd", result.cost_usd)
        
        if result.tier == "TIER_2_FRONTIER":
            span.set_attribute("eval.escalation_reason", "low_confidence")

        return result
```

By tagging telemetry traces with confidence metrics, operations teams can filter production logs for ambiguous outputs and route them directly to domain experts for active learning data annotation.
